## 任务执行偏好

### 任务解耦与并行执行
- **偏好**: 每次任务先进行解耦，然后分多个task并行执行
- **原则**: 
  1. 收到任务后，首先分析任务依赖关系
  2. 将任务拆解为多个独立的子任务
  3. 识别可以并行执行的子任务
  4. 使用多个Tool调用或Task工具并行启动
  5. 最大化并行度以提高效率

### 示例工作流

#### 示例1: 创建多个文件
```
任务: 创建Context相关文件

解耦:
1. context.h (头文件定义)
2. context.cpp (实现文件)
3. cuda_util.h (CUDA工具类)
4. optix_util.h (OptiX工具类)

执行: 并行创建所有4个文件（使用多个Write工具调用）
```

#### 示例2: 验证和测试
```
任务: 验证编译环境

解耦:
1. 检查CUDA版本
2. 检查OptiX版本
3. 检查Visual Studio版本
4. 验证cl.exe路径

执行: 并行执行所有4个检查命令（使用多个Shell工具调用）
```

#### 示例3: 代码重构
```
任务: 重构数据结构

解耦:
1. 修改类型定义
2. 更新使用该类型的文件A
3. 更新使用该类型的文件B
4. 更新测试文件

执行: 
- 步骤1必须先完成（依赖）
- 步骤2-4可以并行执行（独立）
```

## 任务管理偏好

### TODO列表使用
- 对于复杂任务（3+步骤），创建TODO列表
- 实时更新TODO状态
- 完成后立即标记为completed
- 同时只有一个任务处于in_progress状态

### 进度记录
- **不要创建新的markdown文档**
- **更新现有的进度文档**（如`docs/IMPLEMENTATION_LOG.md`或`docs/todo.md`）
- 记录关键决策和技术细节
- 记录遇到的问题和解决方案

## Shell命令偏好

### PowerShell命令语法
- **重要**: PowerShell不支持`&&`语法
- **正确做法**: 多个命令需要分开执行
- **错误示例**: `cd build && cmake ..`
- **正确示例**: 分两次调用Shell工具
  ```powershell
  # 第一次调用
  cd build
  
  # 第二次调用（在第一次成功后）
  cmake ..
  ```

### 命令链接方式
- **分号(;)**: 顺序执行，不管前一个命令是否成功
  ```powershell
  cd build; cmake ..
  ```
- **分开执行**: 最推荐的方式，可以检查每个命令的结果
  ```powershell
  # 调用1
  cd build
  # 调用2（确认调用1成功后）
  cmake ..
  ```

## 编译和测试偏好

### 编译方法
- 优先使用批处理文件（.bat）进行编译
- 批处理文件中调用vcvars64.bat初始化环境
- 避免在PowerShell中直接调用cl.exe（环境变量问题）

### 测试策略
- 创建独立的测试文件验证功能
- 测试文件命名：`<module>_test.cpp` 或 `<module>_test.cu`
- 编译测试以验证类型定义和基本功能
- 测试通过后再继续下一步
